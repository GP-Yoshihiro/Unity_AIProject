# Feature Specification: 古城脱出 ― 五枚の金貨（仮題）

**Feature Branch**: `feature/fantasy-coin-escape-game`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "コイン回収系の脱出ゲーム。ファンタジー系でモンスターとのバトルアクション要素もあり。ゴールは5枚のコインを回収してエリアを脱出してクリアとする。"

## 概要

古城の地下迷宮に閉じ込められた剣士が、迷宮に散らばる金貨5枚を集め、ボスの間の扉を開き、ボスを倒して出口から脱出するゲーム。視点は見下ろし3D、戦闘は剣による近接攻撃。初めての人は1回10分前後で遊び、慣れた人は経過タイマーと区間タイムを使って RTA（最短クリア）を楽しめるようにする。

### 進行の流れ

```
タイトル → 迷宮探索（金貨5枚・ザコ敵・回復薬・セーブ台座）
        → 5枚そろうとボスの間の扉が開く → ボス撃破 → 出口が開く → 出口に触れて脱出 = CLEAR
```

## インタビュー結果（決定事項）

| 項目 | 決定内容 |
|------|----------|
| 視点 | 見下ろし3D（斜め上からの追従カメラ） |
| ボリューム | 1エリア、初見で10分前後 |
| マップ | 古城の地下迷宮（部屋と通路。最奥にボスの間と出口） |
| 戦闘 | 近接攻撃のみ（剣） |
| クリア条件 | 金貨5枚を集める → ボスを倒す → 出口から脱出 |
| ボスの間 | 金貨5枚で扉が開く |
| ザコ敵 | 2種類 |
| ボス | 突進と範囲攻撃（予兆あり） |
| 体力 | ハート5個、回復薬あり |
| 残機 | 3（倒れると1減る。残機があればセーブポイントから復活、0ならゲームオーバー） |
| 復活時 | 金貨は保持。倒したザコ敵は倒したまま。ボスは全快して再戦 |
| セーブ | 祈りの台座の前でキーを押して明示的に保存。保存しても体力は回復しない |
| ゲームオーバー | 最初からやり直し |
| 制限時間 | なし |
| RTA | 経過タイマー表示、ベストタイム保存、区間タイム、即リスタート |
| 操作 | キーボードとゲームパッドの両対応 |
| 画面 | タイトル画面、ポーズ画面 |
| 音 | 効果音、BGM |
| 素材 | Unity Asset Store の無料アセット。入手はユーザーが行う。制作は仮素材で先に進め、後で差し替える |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 迷宮を探索して金貨を集め、脱出する (Priority: P1)

プレイヤーは剣士を操作して迷宮を歩き回り、金貨5枚を集める。5枚そろうとボスの間の扉が開き、ボスを倒すと出口が開いて、出口に触れるとクリアになる。

**Why this priority**: ゲームのゴールそのもの。これがなければゲームとして成立しない。

**Independent Test**: 敵がいない状態でも、金貨5枚の回収 → 扉の開放 → （ボスを仮に撃破済みにして）出口でクリア、まで通しで確かめられる。

**Acceptance Scenarios**:

1. **Given** ゲーム開始直後, **When** 画面を見る, **Then** 金貨 0/5、ハート5個、残機3、経過タイマー 00:00.00 が表示されている
2. **Given** 金貨を持っていない, **When** 金貨に触れる, **Then** 金貨が消え、所持数が1増える。同じ金貨で二重に増えない
3. **Given** 金貨4枚, **When** ボスの間の扉に近づく, **Then** 扉は閉じたままで「金貨が足りない（4/5）」と分かる表示が出る
4. **Given** 金貨5枚目を取った, **When** 取った瞬間, **Then** ボスの間の扉が開き、開いたことが音と表示で分かる
5. **Given** ボスを倒した, **When** 出口に触れる, **Then** CLEAR 画面になり、クリアタイムと区間タイムが表示される
6. **Given** ボスを倒していない, **When** 出口の位置に行く, **Then** 出口は閉じていて通れない

---

### User Story 2 - ザコ敵と剣で戦う (Priority: P1)

迷宮には2種類のザコ敵がいて、プレイヤーに攻撃してくる。プレイヤーは剣で攻撃して倒す。攻撃を受けるとハートが減る。

**Why this priority**: 依頼の中心である「バトルアクション要素」。探索に緊張感を与える。

**Independent Test**: ザコ敵1体だけを置いた部屋で、攻撃して倒す・攻撃を受けてハートが減る、を確かめられる。

**Acceptance Scenarios**:

1. **Given** 敵が剣の届く範囲にいる, **When** 攻撃ボタンを押す, **Then** 敵にダメージが入り、のけぞる。体力が0になると消える
2. **Given** 敵が剣の届く範囲の外にいる, **When** 攻撃ボタンを押す, **Then** 空振りし、敵の体力は変わらない
3. **Given** ハート5個, **When** 敵の攻撃を受ける, **Then** ハートが減り、短い無敵時間の間は追加でダメージを受けない
4. **Given** スライムの索敵範囲外, **When** プレイヤーが近づく, **Then** スライムが追いかけてくる
5. **Given** ゴブリンが巡回中, **When** プレイヤーが見つかる距離に入る, **Then** ゴブリンが巡回をやめて攻撃してくる

---

### User Story 3 - 倒れても残機とセーブポイントで続けられる (Priority: P1)

ハートが0になると倒れて残機が1減る。残機が残っていれば、最後に保存した祈りの台座から復活する。残機が0になるとゲームオーバーになり、最初からやり直す。

**Why this priority**: 10分前後のプレイで、1回のミスで全部やり直しにならないための仕組み。体力・残機・セーブの3つがそろって初めて成立する。

**Independent Test**: 敵の攻撃でわざと倒れ、残機・復活位置・金貨・敵の状態を確かめられる。

**Acceptance Scenarios**:

1. **Given** 残機3、まだ一度も保存していない, **When** ハートが0になる, **Then** 残機2になり、開始地点からハート5個で復活する
2. **Given** 台座Bで保存済み、金貨2枚、その後さらに1枚取って計3枚, **When** 倒れる, **Then** 台座Bから復活し、金貨は3枚のまま
3. **Given** ザコ敵Aを倒し、ザコ敵Bは生きていて追跡中, **When** 倒れて復活する, **Then** Aは倒したまま。Bは初期位置・満タンの体力に戻る
4. **Given** ボスの体力を半分削った, **When** 倒れて復活する, **Then** ボスは体力が満タンに戻っている
5. **Given** 残機1, **When** 倒れる, **Then** 残機0になり GAME OVER 画面が出る。続けると、金貨・敵・回復薬・タイマーなどすべてが初期状態から始まる
6. **Given** 祈りの台座の前でハート2個, **When** 保存キーを押す, **Then** 復活地点が更新され「保存しました」と表示されるが、ハートは2個のまま
7. **Given** 台座から離れている, **When** 保存キーを押す, **Then** 何も起きない

---

### User Story 4 - ボスを倒す (Priority: P1)

ボスの間でボスと戦う。ボスは予兆のあとに突進と範囲攻撃を交互に使う。予兆を見て避け、隙に剣で攻撃して倒す。

**Why this priority**: クリア条件の一部。ゲームの山場になる。

**Independent Test**: ボスの間に直接入った状態から、予兆 → 攻撃 → 隙のサイクルと、撃破で出口が開くことを確かめられる。

**Acceptance Scenarios**:

1. **Given** ボスの間に入った, **When** 戦闘が始まる, **Then** ボスの体力バーが表示され、ボス戦の BGM に切り替わる
2. **Given** ボスが突進の予兆を出した, **When** 予兆の方向から横に避ける, **Then** 突進は当たらない
3. **Given** ボスが範囲攻撃の予兆（地面の円）を出した, **When** 円の外に出る, **Then** ダメージを受けない。円の中にいるとダメージを受ける
4. **Given** 攻撃後のボスの隙, **When** 剣で攻撃する, **Then** ボスの体力が減る
5. **Given** ボスの体力が0になる, **When** 撃破演出が終わる, **Then** 出口が開き、区間タイム「ボス撃破」が記録される

---

### User Story 5 - RTA を楽しむ (Priority: P2)

経過タイマーを見ながら最短クリアを目指す。区間タイムでどこが遅かったかが分かり、ベストタイムが保存される。失敗したらすぐにやり直せる。

**Why this priority**: 制限時間はないが、遊び込みの動機になる。基本の遊び（P1）が完成してから足す。

**Independent Test**: 通しでクリアし、タイマー・区間タイム・ベストタイムの保存とリスタートを確かめられる。

**Acceptance Scenarios**:

1. **Given** タイトルで開始を選んだ, **When** 操作できるようになる, **Then** その瞬間から経過タイマーが動く
2. **Given** プレイ中, **When** ポーズする, **Then** ポーズ中はタイマーが止まる
3. **Given** プレイ中, **When** 倒れて復活する, **Then** タイマーは止まらずに進み続ける（復活にかかった時間もタイムに含む）
4. **Given** 金貨を取った・ボスを倒した・脱出した, **When** その瞬間, **Then** 区間タイムが記録される（金貨1〜5枚目、ボス撃破、脱出の計7区間）
5. **Given** クリアした, **When** CLEAR 画面, **Then** クリアタイム・区間タイム一覧・ベストタイムとの差が表示される
6. **Given** ベストタイムを更新した, **When** ゲームを終了して再起動する, **Then** タイトル画面に新しいベストタイムが表示される
7. **Given** プレイ中（ゲームオーバー画面を含む）, **When** リスタートキーを押す, **Then** 確認なしで即座に最初から始まり、タイマーも 00:00.00 に戻る

---

### User Story 6 - タイトル・ポーズ・音 (Priority: P2)

タイトル画面から始め、プレイ中はポーズできる。攻撃や金貨取得には効果音があり、探索とボス戦で BGM が変わる。

**Why this priority**: 1本のゲームとしての完成度に必要だが、遊びの中核ではない。

**Independent Test**: 起動 → タイトル → 開始 → ポーズ → 再開 → タイトルへ戻る、の画面遷移と、各場面の音を確かめられる。

**Acceptance Scenarios**:

1. **Given** 起動直後, **When** タイトル画面, **Then** 「はじめる」、ベストタイム、操作説明が表示される
2. **Given** プレイ中, **When** ポーズボタンを押す, **Then** ゲームが止まり「再開・最初から・タイトルへ」を選べる
3. **Given** 各操作, **When** 攻撃・被弾・金貨取得・保存・扉の開放・ボス撃破・クリアが起きる, **Then** それぞれの効果音が鳴る
4. **Given** 探索中, **When** ボスの間に入る, **Then** BGM がボス戦の曲に切り替わる

---

### User Story 7 - Asset Store 素材への差し替え (Priority: P3)

最初は Unity 標準の図形（仮素材）でゲームを完成させる。ユーザーが Asset Store で入手した素材を取り込んだら、見た目と音を差し替える。差し替えでゲームの動きは変わらない。

**Why this priority**: 素材の入手はユーザーの作業に依存するため、ゲームの完成をそれに待たせない。

**Independent Test**: 1種類（例: スライム）の見た目だけを差し替え、当たり判定と動きが変わらないことを確かめられる。

**Acceptance Scenarios**:

1. **Given** 仮素材で完成したゲーム, **When** キャラクターの見た目のモデルを差し替える, **Then** 移動・攻撃・当たり判定はそのまま動く
2. **Given** 素材がまだない, **When** ゲームを遊ぶ, **Then** 仮素材のままでも最後までクリアできる

---

### Edge Cases

- 5枚目の金貨を取った瞬間に倒れた: 金貨5枚は保持し、扉は開いたまま。復活後にボスの間へ入れる
- ボスの最後の一撃と、プレイヤーが倒れるのが同じ瞬間: ボス撃破を優先する（出口が開き、区間タイムを記録してから倒れる処理）
- ボス戦中に倒れて復活: ボスは満タンで初期位置に戻る。開いた扉はそのまま
- 一度も保存せずに倒れた: 開始地点から復活する
- 回復薬をハート満タンで取った: 取らずにその場に残す（無駄に消費しない）
- 復活時に回復薬はどうなるか: 使った回復薬は戻らない（金貨と同じく進捗として扱う）
- ゲームオーバー後: 金貨・敵・ボス・回復薬・扉・保存地点・残機・タイマー・区間タイムをすべて初期化する
- 即リスタートの誤操作: RTA 向けに確認なしで即やり直す。誤操作対策はしない（ポーズ画面の「最初から」も同じ動作）
- ポーズ中にリスタートキー: ポーズを解除して最初から始める
- 被弾の無敵時間中に、複数の敵から同時に攻撃された: 1回分のダメージだけ受ける
- 出口の上で倒れた（撃破後）: 出口に触れた時点でクリアが確定していれば CLEAR を優先する
- キーボードとゲームパッドを同時に使う: どちらの入力も受け付ける

## Requirements *(mandatory)*

### Functional Requirements

**探索と進行**

- **FR-001**: プレイヤーは見下ろし3D視点で、迷宮内を8方向に移動できなければならない
- **FR-002**: カメラはプレイヤーを斜め上から追従し、プレイヤーが常に画面内に見えていなければならない
- **FR-003**: 迷宮には金貨が5枚置かれ、触れると回収され、所持数が1増えなければならない。同じ金貨は二重に数えない
- **FR-004**: ボスの間の扉は、金貨5枚を持つまで閉じていなければならない。5枚目を取った時点で開く
- **FR-005**: 出口はボス撃破まで閉じていなければならない。撃破後に開き、触れるとクリアになる

**戦闘**

- **FR-010**: プレイヤーは剣で前方の扇形の範囲に近接攻撃できなければならない。攻撃には再使用までの短い間隔がある
- **FR-011**: プレイヤーは回避（短い距離のダッシュ）ができ、回避中は無敵でなければならない
- **FR-012**: ザコ敵は2種類とする。スライム（近づくと追いかけて体当たり）とゴブリン（決まった道を巡回し、見つけると武器で攻撃）
- **FR-013**: 敵は体力を持ち、0になると倒れて消えなければならない
- **FR-014**: プレイヤーは被弾後、短い無敵時間を持たなければならない
- **FR-015**: ボスは「突進」と「範囲攻撃」を持ち、どちらも攻撃前に予兆を見せなければならない。突進は向きを示す線、範囲攻撃は地面の円で示す
- **FR-016**: ボスの体力はボス戦中にバーで表示しなければならない

**体力・残機・セーブ**

- **FR-020**: プレイヤーの体力はハート5個とする
- **FR-021**: 迷宮に回復薬を置き、触れるとハートが回復しなければならない（上限5個）
- **FR-022**: 残機は3から始まる。ハートが0になると残機が1減る
- **FR-023**: 倒れた後に残機が1以上あれば、最後に保存した祈りの台座（未保存なら開始地点）から、ハート5個で復活しなければならない
- **FR-024**: 復活時、金貨・使った回復薬・倒したザコ敵・開いた扉は倒れる直前のまま保持しなければならない。生きているザコ敵は初期位置と満タンの体力に戻る。ボスは満タンの体力で初期位置に戻る
- **FR-025**: 残機が0になったらゲームオーバー画面を出し、続けると全ての状態を初期化して最初から始めなければならない
- **FR-026**: 祈りの台座の近くで保存キーを押すと、復活地点がその台座に更新されなければならない。保存しても体力は回復しない
- **FR-027**: 保存できる範囲にいるときは、保存キーの案内を表示しなければならない

**RTA**

- **FR-030**: 経過タイマーを画面に常に表示しなければならない（分:秒.百分の一秒）
- **FR-031**: タイマーはプレイ開始で動き出し、脱出で止まり、ポーズ中は止まらなければならない。倒れてから復活するまでの時間は含む
- **FR-032**: 区間タイムを、金貨1〜5枚目の取得、ボス撃破、脱出の7回記録しなければならない
- **FR-033**: クリア時に、クリアタイム、区間タイム一覧、ベストタイムとの差を表示しなければならない
- **FR-034**: ベストタイムと、そのときの区間タイムを PC に保存し、再起動後も保持しなければならない
- **FR-035**: プレイ中はいつでもリスタートキーで、確認なしに最初からやり直せなければならない。タイマーと区間タイムも初期化する

**画面・音**

- **FR-040**: タイトル画面に「はじめる」、ベストタイム、操作説明を表示しなければならない
- **FR-041**: ポーズ画面で「再開」「最初から」「タイトルへ」を選べなければならない
- **FR-042**: HUD に金貨数（n/5）、ハート、残機、経過タイマーを表示しなければならない
- **FR-043**: 効果音を、攻撃・敵への命中・被弾・金貨取得・回復・保存・扉の開放・ボスの予兆・ボス撃破・クリア・ゲームオーバーで鳴らさなければならない
- **FR-044**: BGM を探索とボス戦で切り替えなければならない

**操作**

- **FR-050**: キーボードとゲームパッドの両方で、すべての操作ができなければならない。入力は Input System のアクションでまとめて定義する

| 操作 | キーボード | ゲームパッド |
|------|-----------|-------------|
| 移動 | WASD / 矢印キー | 左スティック / 十字キー |
| 攻撃 | J / Space | South（A / ×） |
| 回避 | K / Left Shift | East（B / ○） |
| 保存（台座の前） | E | North（Y / △） |
| ポーズ | Esc | Start |
| 即リスタート | R | Select（View） |
| 決定（メニュー） | Enter / Space | South |

**素材**

- **FR-060**: 見た目と音は差し替えやすい構造にしなければならない。キャラクター・敵・ボス・金貨・台座・扉などは、動きと当たり判定を持つ本体と、見た目のモデルを分ける
- **FR-061**: Asset Store 素材が入るまでは、Unity 標準の図形と色で、区別しやすい仮の見た目にしなければならない

**検証しやすさ**

- **FR-070**: unity-cli でゲームの状態を取得できるようにしなければならない（金貨数、ハート、残機、復活地点、経過タイム、区間タイム、ボスの体力、扉と出口の開閉、現在の画面）

### Key Entities

- **プレイヤー（剣士）**: 位置、ハート（0〜5）、無敵中かどうか、攻撃・回避の再使用待ち
- **ラン（1回のプレイ）**: 金貨の所持数と取得済みの金貨、残機、復活地点、倒したザコ敵、使った回復薬、扉と出口の状態、経過タイム、区間タイム
- **金貨**: 5枚。それぞれ固有の ID を持ち、取得済みかどうか
- **ザコ敵**: 種類（スライム / ゴブリン）、体力、初期位置、倒されたかどうか
- **ボス**: 体力、現在の行動（待機・予兆・突進・範囲攻撃・隙）、初期位置
- **祈りの台座**: 位置、復活地点として使うかどうか
- **回復薬**: 回復量、使われたかどうか
- **記録**: ベストタイムとその区間タイム（PC に保存）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めて遊ぶ人が、8〜12分程度で通しでクリアできる（ゲームオーバーなしの場合）
- **SC-002**: 最短ルートを知っている人なら、3分以内でクリアできる（RTA の目安）
- **SC-003**: 「金貨5枚 → ボスの間 → ボス撃破 → 脱出」の流れを、説明なしで画面表示だけから理解できる
- **SC-004**: ボスのすべての攻撃は、予兆を見てから避けられる（予兆から攻撃まで0.6秒以上）
- **SC-005**: User Story 1〜6 の受け入れシナリオがすべて、unity-cli による操作と状態取得、および画面の画像で確認できる
- **SC-006**: 即リスタートを押してから、再び操作できるまで1秒以内
- **SC-007**: 素材を差し替えても、受け入れシナリオの結果が変わらない

## Assumptions

インタビューで決めていない細かい数値は、以下を初期値とする。遊んでみて調整する。

- **数値の初期値**: スライム体力2・ゴブリン体力3・ボス体力20、剣の攻撃力1、ザコ敵の攻撃はハート1個、ボスの突進はハート2個・範囲攻撃はハート1個、被弾後の無敵1.0秒、回避は約3m・0.3秒（その間無敵）・再使用0.8秒、回復薬はハート2個分
- **配置数**: 祈りの台座3か所（迷宮の前半・中盤・ボスの間の手前）、回復薬3個、ザコ敵は合計10〜14体程度
- **迷宮の構成**: 開始の広間、金貨の部屋が5つ前後（1部屋1枚を基本とし、隠し通路や遠回りでルート選びに意味を持たせる）、ボスの間、出口。1シーンで作る
- **残機の数え方**: 「残機3」は今のプレイヤーを含む。3回目に倒れるとゲームオーバー
- **回避**: インタビューの選択肢では明示していないが、ボスの予兆を見て避ける遊びのために入れる
- **ボスの間**: 入ると戦闘開始。扉は戦闘中も閉じない（逃げて立て直せる）
- **ベストタイムの保存**: PC 内（PlayerPrefs）に保存する。オンラインのランキングは作らない
- **素材**: Asset Store の素材（ファンタジーのキャラクター、ダンジョンの床・壁、モンスター、効果音、BGM）はユーザーが入手して Unity に取り込む。AI は取り込まれた素材の組み込みを担当する。素材の候補は計画の段階で挙げる
- **レンダリング**: 現在のプロジェクト設定（Built-in レンダーパイプライン）を使う。素材が URP 専用の場合は、そのときに相談する

## Out of Scope

- 複数のエリア・ステージ、マップの自動生成
- 遠距離攻撃・魔法、装備の強化や成長要素
- オンラインのランキング、マルチプレイ
- セーブデータの途中保存（ゲームを終了したら最初から。保存はベストタイムのみ）
- 実行ファイルのビルドと配布
- モバイル・タッチ操作
